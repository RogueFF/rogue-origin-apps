# Capataz v2 Implementation Plan — the agent runs on FERN on the subscription

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task.

**Goal:** Replace the worker-side Anthropic API parse with a FERN-hosted `claude -p` relay ("Capataz"), so foremen text a Twilio number and get conversational Spanish replies on Koa's subscription, with the worker keeping the clock, the rows, and the Twilio credentials.

**Architecture:** The worker (`rogue-origin-api`) stays the mailbox and the state machine: Twilio webhook → dedupe → commands handled deterministically, chat texts queued in `harvest_sms_inbox`. A new kit deployment `Desktop\Dev\capataz-bot` (copy of `riego-bot`) polls the worker every 2.5 s, runs one `claude -p --resume` session per foreman phone with a Spanish persona, writes reports through a new farm-bridge MCP tool `log_hourly_crew` → `POST /api/harvest?action=hourly_set`, and sends replies through `POST /api/harvest?action=sms_send`. The API parse module is deleted.

**Tech stack:** Cloudflare Workers (plain JS) + D1; Python 3 `claude_relay` kit (asyncio, portalocker, `claude -p --output-format stream-json`); farm-bridge MCP worker (TypeScript, `@modelcontextprotocol/sdk`, `zod`).

### Task W2: Queue chat texts, keep commands inline, add the three host endpoints, delete the API parse

**Files:** Modify `workers/src/handlers/harvest-hourly-d1.js`, `workers/src/lib/harvest-hourly.js`; delete `workers/src/lib/harvest-hourly-parse.js` and `workers/test/harvest-hourly-parse.test.mjs`; add `workers/test/harvest-hourly-sms.test.mjs` for the new pure helpers.

Read the handler end to end first. Then:

1. **`processInbound`** — after dedupe and foreman lookup: `classifyInbound`. For `start`/`stop`/`help`: handle exactly as today and `UPDATE harvest_sms_inbox SET kind='command', processed=1, replied_at=? WHERE message_sid=?`. For `answer` (chat): do **not** parse. Leave the row `kind='chat', processed=0` and return `[]` (no reply — the relay replies). Unregistered numbers: mark `processed=1, kind='ignored'` so they never reach the relay. `hourly_simulate` keeps its contract: returns `{ replies }` for commands and `{ queued: true, message_sid }` for chat.
2. **Extract the write core** from `answer()` into `applyHourlyReport(db, env, { foreman, hour, values, notes, rawText, now })` returning `{ row, missing, invalid, confirmText | askMissingText, refused? }` — the existing logic: target row (hour prefix → newest open → just-ended), future-hour refusal, `getOrCreateRow` with `asked_at NULL` for backfills, `validateCounts`, additive COALESCE UPDATE, re-read, status write with `nudged_at`, `normalizeNotes`, out-of-range prefix. No model call anywhere. Delete `parseReply` import and the try/catch around it; delete `temporaryErrorText` and `notUnderstoodText` from the lib (the relay owns wording now) and their tests.
3. **Bearer helper** `requireSmsKey(request, body, env)` — `env.HARVEST_SMS_KEY` required (throw `INTERNAL_ERROR` "HARVEST_SMS_KEY not configured" if unset), `extractPassword` + `constantTimeEqual`, else `UNAUTHORIZED`. Put it in `workers/src/lib/auth.js` next to `requireAuth` as `requireBearer(request, body, env, envKey, label)` and use it.
4. **`GET ?action=sms_poll&limit=N`** (default 20, cap 100): select `kind='chat' AND processed=0` ordered by `received_at`, mark `processed=1, delivered_at=now` per row (`WHERE message_sid=? AND processed=0`), and return `{ messages: [ { message_sid, from_phone, body, received_at, context } ] }` where `context` is:
   ```json
   { "foreman": {"name","barn","barn_label","active","active_since"},
     "open_row": {"hour_start","hour_range","status","missing":[...],"values":{...six...},"notes"} | null,
     "just_ended_hour": "09:00" | null,
     "today": {"date","total_racks","complete_hours":N,"missing_hours":[...],"rows":[{hour_start,status,racks}]},
     "now_pacific": "10:07" }
   ```
   Build the context from the same queries `readDay` and `answer()` already use. Skip (leave processed=0) any row whose phone has no foreman — should not happen after step 1, but never hand the relay an unknown number.
5. **`POST ?action=sms_send {to, text}`**: `to` must be a registered foreman phone (`NOT_FOUND` otherwise); text is run through `gsmSafe(text)` (new pure lib helper: strip diacritics via NFD + remove combining marks, replace `¿¡` with nothing, `ñ`→`n`, collapse whitespace) and refused with `VALIDATION_ERROR` if over 480 characters (3 segments). Calls `sendSms`; returns `{ sent: boolean, text }` (`sent:false` when Twilio is unconfigured — local dev logs it). Also `UPDATE harvest_sms_inbox SET replied_at=? WHERE from_phone=? AND replied_at IS NULL AND processed=1` (best-effort marker; ignore changes count).
6. **`POST ?action=hourly_set`** `{ phone, hour_start?, cutters?, cutter_water_spiders?, drivers?, hangers?, hanging_water_spiders?, racks?, notes?, raw_text? }`: foreman by phone (`NOT_FOUND`), then `applyHourlyReport`. Returns `{ ok: true, row: {...}, missing: [...], invalid: [...], reply: "<confirmText or askMissingText, with the out-of-range prefix>" }` or `{ ok: false, reason: 'future_hour' | 'no_hour_yet', reply: "<futureHourText or the no-hour text>" }`. HTTP 200 in both cases; only auth/validation errors throw.
7. **`hourly_pending` count** exposed on `?action=hourly` read (`pending_sms: N`) for the dashboard card to show "N texts waiting for Capataz".
8. Add the three actions + `hourly_set` to `HOURLY_ACTIONS` and the header comment.

**Pure helpers + tests** (`lib/harvest-hourly.js`, `test/harvest-hourly-sms.test.mjs`): `gsmSafe`, `smsSegments(text)` (GSM-7 160 / 153 per segment after the first; count as 1 segment ≤160), and `buildPollContext(rows, foreman, now)` if you make the context assembly pure (recommended: the handler fetches rows, the lib shapes the JSON). `npm test` must pass; expect the parse tests gone and the new ones added.

Commit `feat(harvest): queue chat texts for the Capataz relay; sms_poll, sms_send, hourly_set; drop API parse`.
